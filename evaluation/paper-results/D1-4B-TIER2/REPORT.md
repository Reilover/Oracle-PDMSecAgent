## 5. 三轴总结（4B vs 0.8B 重层）

| 轴 | 0.8B@8023 | 4B@8018 | Δ |
|---|---|---|---|
| **升级增益**（299 窗串联−仅L1，tactic） | +0.037 | **+0.137** | **×3.7** |
| **系统精度**（tactic / exact，τ=0.90） | 0.554 / 0.437 | 0.622 / 0.458 | +0.068 / +0.021 |
| **自动化带宽**（τ=0.75 auto 份额） | 81.4% | 77.2% | −4.2pp（4B conf 更平） |
| **带宽×精度甜点**（τ=0.75） | 0.432 | **0.456** | +0.024 |
| **延迟成本**（tier2 P50 / 端到端 P50） | 111ms / 1061ms | 166ms / 1110ms | +55ms / +4.5% |
| 送人工题占比 | 53.6% | 58.0% | +4.4pp |

**结论**：
1. **升级增益**：4B 重层把串联增益从 +0.037 放大到 **+0.137**（tactic），"escalation 沿精度-成本前沿移动"的论文表述在 4B 重层下成立（0.8B 版的净负/微弱结论是重层容量不足所致）；initial_access 双盲减半是主要来源。
2. **系统精度**：+0.068 tactic，非规则段系统口径 0.818 已逼近单模型 0.850——系统精度与单模型的残余差距几乎全部留在规则层（假阳性 101/101），换重层模型不解决、需改规则层（A3b 消融）。
3. **延迟成本**：+55ms/升级窗（+49%），端到端仅 +4.5%（tier1 CPU 主导）；GPU 口径下端到端 ~195ms 量级。**4B 重层以 ~50ms/窗的成本换取最大的一档精度增益**——在延迟预算允许时 4B 是明确优选；0.8B 的定位是"带宽优先"（同 τ 下 auto 份额高 4.2pp）的轻量档。
4. **代价面**：4B conf 分布更平 → 同 τ 下 escalate 更多（353 vs 268 题）、人工队列更长；若部署 4B 重层可将 τ 降到 0.75-0.80 对冲（auto 77% 且 tactic 0.590 仍高于 0.8B 版任何档）。
